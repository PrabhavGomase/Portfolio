Problem

Sorting algorithms are usually taught as pseudocode — hard to build intuition for how they actually behave on real data, and why one outperforms another.

Approach

  • Render an array as bars on a canvas, redrawing on every comparison/swap.
  • Implemented Bubble, Selection, Insertion, Merge, and Quick Sort as step-by-step generators so each comparison is visible.
  • Adjustable array size and animation speed to compare algorithm behavior at different scales.

Problem

Most to-do app tutorials skip persistence — refresh the page and everything's gone.

Approach

  • Add, delete, and mark tasks complete with a minimal, responsive interface.
  • Task filtering across All / Pending / Completed views.
  • State persisted to LocalStorage so tasks survive a page reload.

Implementation note

Filtering is derived, not stored — the task list is the single source of truth, and the active filter just changes which items get rendered from it. That keeps add, toggle, and delete simple and avoids duplicated state going out of sync.

    Problem

    Weather data is only useful if it's current — the dashboard needed to fetch on demand rather than ship with stale numbers baked in.

    Approach

    • City input triggers an async call to the OpenWeather API.
    • Displays temperature, humidity, and wind speed once the response resolves.
    • Built entirely on the Fetch API — no external HTTP library.

    Implementation note

    This embedded demo uses sample data instead of a live key, so it works without configuration. The real project's fetch layer wraps each request in a try/catch and shows a fallback message on a failed lookup or bad city name, rather than leaving the UI blank.

    Notes

    Short write-ups on things I ran into while building the projects above. Starter entries — edit freely.

    DEV LOG · SORTING VISUALIZER

    Why Quick Sort still beats Bubble Sort in practice

    On paper, Bubble and Quick Sort both degrade to O(n²) in the worst case. The difference shows up in the visualizer at larger array sizes: Quick Sort's partitioning does far fewer comparisons on already-scattered data, while Bubble Sort keeps re-scanning the same range. Watching it animate makes the average-case gap obvious in a way the Big-O notation alone doesn't.

    DEV LOG · TASK MANAGER

    Filtering state without a framework

    The easy mistake with an All/Pending/Completed filter is storing three separate lists and trying to keep them in sync. Keeping one array as the source of truth and computing the filtered view on render removed an entire class of bugs — at the cost of re-filtering on every render, which is irrelevant at this scale.

    DEV LOG · WEATHER DASHBOARD

    Handling a Fetch call that can fail

    An async weather lookup can fail in more ways than it can succeed: bad city name, network drop, rate limit. Wrapping the fetch in try/catch and giving the UI an explicit "couldn't find that city" state — instead of silently leaving the previous result on screen — made the dashboard feel a lot more trustworthy.
